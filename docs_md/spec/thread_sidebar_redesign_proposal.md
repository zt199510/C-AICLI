# C-AICLI 左侧会话历史栏重构提案

状态：方案 A 已确认并实施。本文保留 UI、交互、代码落点和验收标准；实施结果已通过组件测试、类型检查、Lint、无障碍检查、生产安全检查、正式构建与本地浏览器视觉验收。

## 1. 推荐结论

第一阶段采用“当前工作区内的 Codex 风格会话导航”，不直接实现参考图中的全局多项目树。

原因：当前桌面端一次只打开一个 workspace，`thread.list` 也强制按当前 `workspaceId` 查询。现有数据已足够支持标题搜索、状态筛选、时间分组、状态图标、重命名和归档；多项目总览、持久化置顶和全文搜索会牵涉 Thread Store、Application、RPC 合约与控制器，不适合混入纯 UI 重构。

推荐的第一阶段范围：

- 288 px 默认侧栏，允许在 240–360 px 内做会话期调整；第一阶段不持久化宽度。
- 固定工作区头部、固定“新建对话”、标题搜索与状态筛选。
- 会话按“今天 / 昨天 / 最近 7 天 / 更早”分组。
- 当前会话使用柔和整行选中态；进行中、失败等状态使用小图标并带无障碍文本。
- 行内按钮收敛为悬浮或键盘聚焦时出现的“更多”菜单，第一阶段只包含现有的重命名与归档。
- 宽屏手动收起后显示 64 px 图标栏；窄屏继续使用抽屉，关闭时完全隐藏。
- 搜索只匹配已加载的最多 200 条标题；保留“结果已截断”的明确提示。
- 修正当前状态映射：协议合法状态是 `idle/running/waiting-for-approval/canceling/canceled/failed/completed/archived`，不能继续用测试中的虚构 `active` 状态代替。

## 2. 信息架构

```text
侧栏 288 px
├─ 固定头部
│  ├─ C-AICLI / 当前工作区路径
│  └─ 收起按钮
├─ 固定主操作
│  ├─ 新建对话
│  └─ 搜索输入 + 状态筛选
├─ 独立滚动区
│  ├─ 当前工作区标题
│  ├─ 今天
│  ├─ 昨天
│  ├─ 最近 7 天
│  └─ 更早
└─ 固定底部
   └─ 已归档
```

不同时展示“最近列表”和项目内相同会话，避免同一条会话在侧栏出现两份且状态不一致。

## 3. 核心 UI 规格

| 项目 | 建议值 |
|---|---:|
| 默认宽度 | 288 px |
| 可调整范围 | 240–360 px |
| 折叠图标栏 | 64 px |
| 固定头部 | 56 px |
| 主操作行 | 36–40 px |
| 会话行 | 36 px |
| 侧栏内边距 | 12 px |
| 图标 | 16 px |
| 行圆角 | 8–10 px |
| 动画 | 120–160 ms，并遵循减少动态效果设置 |

视觉继续使用现有 C-AICLI 的暖灰、米白与森林绿语义 Token，不引入新的品牌色。正文、辅助文本、选中、悬停、键盘焦点和危险状态必须各自可辨识；状态不能只依赖颜色。

## 4. 交互状态

### 默认态

- 当前工作区展开，会话按本机时区的自然日分组。
- 组内沿用服务端 `updatedAtUtc` 倒序。
- 完成态默认不显示状态徽章，降低视觉噪声；进行中和失败保留图形状态。
- 默认历史不混入归档会话；归档只在独立视图中出现。

### 搜索态

- 搜索框匹配会话标题，中文、英文、路径和 Emoji 都按不区分大小写的包含关系处理。
- `Ctrl/Cmd + K` 聚焦搜索；`Esc` 清空并返回完整历史；上下键移动，`Enter` 打开。
- 筛选继续支持 All、Active、Completed、Failed、Archived，但改为紧凑筛选面板，不长期占用一整行选择框。
- 无结果显示搜索词，并提供“清除筛选”和“新建对话”。

### 更多菜单

- `···` 只在悬停或 `focus-within` 时显示，不挤压状态图标。
- 第一阶段菜单只有“重命名”和“归档”，复用现有 mutation 与 revision 校验。
- `Shift + F10` 打开菜单，`Esc` 关闭并把焦点还给触发按钮。
- 归档继续显式确认；不新增删除操作。
- 归档当前会话成功后选择下一条可用的未归档会话；没有可用项时进入新对话草稿，不再重新选中已归档项。

### 折叠与窄屏

- ≥ 1121 px：默认 288 px；用户可在当前应用会话中调整到 240–360 px，双击分隔线恢复 288 px。
- 900–1120 px：默认 240 px；检查器保持隐藏。
- ≤ 899 px：使用最大 288 px / 88vw 的覆盖抽屉；与右侧检查器互斥。
- 宽屏手动收起显示 64 px 图标栏；窄屏收起不保留图标栏，以免占用主聊天区域。

## 6. 实施顺序

### 阶段 A：测试基线与纯数据模型

1. 扩充预览 fixture 和 `ThreadSidebar` 单元测试，先固定现有选择、重命名、归档及焦点行为。
2. 新增无副作用的标题搜索、合法八状态映射、状态筛选、日期分组函数及边界测试；修复 Active 过滤错误包含 canceled 的问题。
3. 日期分组基于用户本机时区，避免直接按 UTC 日期截断。

### 阶段 B：侧栏结构与视觉

1. 把固定头部、主操作、滚动历史和固定归档入口拆成明确区域。
2. 将现有 select 改为搜索框 + 筛选按钮。
3. 把状态 chip 改成安静的状态图标，并实现选中、悬停、聚焦三种独立状态。
4. 把重命名和归档按钮合并到统一更多菜单，保留显式归档确认。

### 阶段 C：布局状态与响应式

1. 扩展 `useShellPanels`，支持展开、宽屏图标栏和窄屏隐藏/抽屉。
2. 增加会话期可调整宽度和默认宽度恢复。Renderer 生产安全检查明确禁止 `localStorage/indexedDB`，因此第一阶段不做持久化。
3. 验证侧栏与右侧检查器在各窗口宽度下互斥且焦点可恢复。

### 阶段 D：验证与视觉回归

1. 运行侧栏定向 Vitest、TypeScript、ESLint 和无障碍静态检查。
2. 构建 renderer 并在 `?preview=week89` 做人工视觉检查。
3. 运行 1440×900、1024×768、800×900 的 Electron 视觉矩阵。
4. 验证 200 条记录、超长中文/英文/路径、空结果、截断提示、加载错误和归档视图。

## 7. 验收标准

- 240、288、360 px 三种宽度下，标题、状态和菜单无重叠或横向滚动。
- 当前会话、悬停、键盘焦点和失败状态不依赖同一种视觉提示。
- 搜索、筛选、重命名、归档、展开/收起均可只用键盘完成。
- `Esc` 关闭搜索/菜单/归档确认后，焦点回到合理触发点。
- 200 条会话滚动顺畅；当前 200 条服务端上限不额外引入虚拟列表复杂度。
- 会话期宽度调整与默认宽度恢复正确；窄屏不会错误保留 64 px 图标栏。
- 现有会话选择不会启动新 turn；rename/archive 继续使用 expected revision，错误仍可见。
- `npm run typecheck`、`npm run lint`、`npm run check:accessibility`、定向 Vitest、renderer build 和视觉 E2E 全部通过。

## 8. 本次明确不做

- 全局多工作区项目树。
- 会话内容全文索引。
- 置顶、移动到项目、未读同步或跨设备状态。
- 删除会话或新增后端 mutation。
- 通过 Renderer `localStorage/indexedDB` 持久化侧栏偏好；若后续需要，必须设计 Main/AppHost 权威设置存储。
- 建立全应用 i18n。用户确认方案 A 时明确要求中文，因此本次仅将会话侧栏及其必要入口中文化；其他产品界面的系统性本地化仍不在本阶段范围内。
- 顺手重构整个桌面壳层或全局 CSS。

这些能力可在第二阶段单独设计合约和迁移方案，避免 UI 重构与数据模型迁移相互阻塞。
